# `security/` — This Repo's Own Audit Trail

Everything about **this repository's** own pipeline, release process, and
security posture lives here — as opposed to `audit/`, which is the portable
*tool* this playbook ships for auditing **other** repos, and `templates/`,
which holds the blank templates that tool's reports are based on.

This mirrors the layout `docs/TECH_STACK.md` §3 prescribes for any project that
adopts this playbook (`security/` = your own CYB/BIA reports; `audit/` +
`templates/` = the vendored, reusable tooling). The playbook dogfoods its
own convention here.

## Files

| File | What it is |
| --- | --- |
| [`PIPELINE_AND_RELEASE_REVIEW.md`](PIPELINE_AND_RELEASE_REVIEW.md) | The point-in-time manual review of this repo's CI/CD, release automation, and audit-script correctness — what was found, what was fixed, what's still open. **Start here.** |
| `reports/CYB_report_<date>.md` | Standards-mapped report auto-generated by running `../audit/run-audit.sh .` against this repo (self-test / dogfooding). |
| `reports/audit-report_<date>.md` | The flat PASS/WARN/FAIL companion to the CYB report, same run. |

## Re-running the self-audit

```bash
bash ../audit/run-audit.sh .          # from the repo root: bash audit/run-audit.sh .
```

```powershell
powershell -ExecutionPolicy Bypass -File audit\run-audit.ps1 -RepoPath .
```

The script writes fresh, timestamped reports to `audit/reports/` (gitignored
— generated output). Copy the ones worth keeping into `security/reports/`
here with a clean `_<date>.md` name, the same way the ones currently in this
folder were produced, so there's a durable record instead of only the
latest run.

## CI does this automatically

`.github/workflows/ci.yml`'s `self-audit` job runs the same command on every
push/PR and uploads the reports as a build artifact — see
`PIPELINE_AND_RELEASE_REVIEW.md` §3 for the full pipeline description.
